- **Benchmarks: the push to `dev` raises a drift alarm.** `benchmarks.yml`'s `update-baseline` job captures every gated row on the merged tree and replaces the rolling baseline; it now also compares that capture with the baseline it replaced, through `compare.py`'s thresholds, and the run is red when a row has moved past its fail threshold or is gone. The step runs after the baseline is pushed, so a red never freezes the baseline: a count changed on purpose is red on one push and is the next push's reference. A pull request's capture is scoped to the rows its change can reach and passes on a warn, so until now a row that moved under a scoped-out pull request, or by several warns in a row, was absorbed into the baseline with no signal. The comparison is one script, `scripts/bench/drift_report.sh`, which the nightly full-weight capture's `nightly_drift.sh` now calls too; its table shows the delta as a percentage (it printed the report's fraction with a percent sign).
