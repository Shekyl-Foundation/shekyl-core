- **Benchmarks: the push to `dev` raises a drift alarm.** `benchmarks.yml`'s `update-baseline` job captures every row of the pull-request set on the merged tree and replaces the rolling baseline, then compares that capture with the baseline it replaced (`scripts/bench/drift_report.sh`, the comparator `nightly_drift.sh` also runs on the nightly full-weight set). A row past its fail threshold, or a row gone, turns the run red; the log names the row, and the dev-red reporter opens the issue. The step runs after the push, so a red never freezes the baseline: a count that crossed the fail threshold is red on that push and is the next push's reference. A warn does not redden the run, and because the baseline has moved, a row that stays inside the warn band on each push is not accumulated. A pull request still captures only the rows its change can reach and still passes on a warn, so a row that moved past the fail threshold under a pull request that did not run it is red here. The log is `compare.py`'s, which is also what the pull-request comment formats: the percentage is the fractional delta times one hundred, and a missing row is named.
