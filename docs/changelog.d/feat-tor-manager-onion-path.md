- **The Tor Manager says whether the onion path works; the dialer's judge only asks** (Rick, 2026-11-15; `DIALER_OUTAGE_EVIDENCE.md` §3.3, `TOR_SUPERVISOR.md` §4.5a). The judge is decoupled from every connector: for an uncertain failure it asks the dialing connector for one path reading taken after the failure (`PathSource`, `shekyl-transport-layer`), counting it on a working reading and excusing it on an impaired one or none within the connector's declared wait. The bracket's before side, the byte clock, the stream observations and the `Corroboration` declaration are deleted, and `shekyl-dialer` reaches no Tor crate (`scripts/ci/check_dialer_no_tor.sh`). The Tor connector's readings are the Tor Manager's: working from a check whose probe came back with its directory check held, a completed onion dial or a new inbound Tor session; impaired from Tor's own statements or the two-miss verdict; never from held-session bytes. A failed dial with no reading after it makes the manager run its check, at most once per 15 minutes (`CHECK_SPACING`); the Tor wait is 19 minutes. Clearnet reads its own outbound sessions, as before. Under an operator's Tor there is no check, so dead onion addresses fade more slowly. The quiet status line stands only when the manager's reading is impaired, peers are known and a Tor dial failed since; the "No peers are known yet." sentence is gone, and the `tor_quiet` status field is now `{"unreached": {"age": s}}` in place of `empty` and `failing`. The per-connector dial tally is `LinkTally`, without the last sign of life. The directory-check parser test now uses the fetch failures tor 0.4.9.14 emits; it never emits `QUERY_RATE_LIMITED`.
