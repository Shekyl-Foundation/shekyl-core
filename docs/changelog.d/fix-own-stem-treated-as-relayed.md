- **Relay privacy: once sent, a node's own transaction is treated exactly like one it relays** (`DAEMON_RELAY_PRIVACY.md` §92.5c item 3; Rick, 2026-11-18). A node used to arm a fixed 1,176 s retry after stemming its own transaction, where a relayed stem draws a random embargo. A stem peer that dropped every stem a node sent it could sort the node's own transactions from the relayed ones by that timing. The fixed interval is gone: every stemmed transaction draws its deadline from the same random embargo timer, and on fire takes the same two steps, one re-stem to the alternate and then a broadcast. For a wallet this changes how long a dropped own transaction takes to recover: the wait is now random, with the embargo timer's mean (511 s on Tor, 194 s on clearnet) for each of its two fires, and it may come sooner or later than the old fixed time. The age at which the daemon reports an unpublished own transaction overdue (2,352 s) is unchanged and is status only.
- **Relay: a stem is recorded when its write lands.** The embargo of a re-stem, and of a held own transaction's first send, used to be armed before the write. A first send whose write fails now stays unsent and is planned again on the 300 s grid; a re-stem whose write fails draws one more embargo, and its next fire broadcasts. The relay embargo's two live walks move to a nightly leg of their own (`GATE_LANE=embargo`), because they now wait for a random fire.
