- **Benchmarks: the measurement ledger writes every commit id in full.** The ledger held commit ids of four lengths (149 of nine characters, 349 of ten, one of twelve, 17 of forty). A prefix unique today can become ambiguous as the repository grows, and `scripts/ci/check_measurement_ledger.py` would then fail on a row nobody touched. Every id is rewritten once, mechanically, to its full 40 hex: each was resolved with `git rev-parse --verify <id>^{commit}`, and none failed to resolve or was ambiguous (306 distinct ids, 516 occurrences). The rewrite is its own commit, a pure substitution. The check now refuses any id in the ledger under review (`through`, `capture_rev`, `stale_since`, a toolchain entry's `commit`) that is not exactly 40 lowercase hex, and still refuses one that names no commit. A parent ledger written before the rule is still read. The selftest plants a short id in each place, an upper-case one and an unknown one.
