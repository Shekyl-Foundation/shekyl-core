- **Daemon: a stop the operator asked for is announced, not a warning** (`INPUT_GRAMMAR.md` IG-14; alpha.11 bug hunt; Rick, 2026-11-06). Every service stop on the alpha.11 fleet logged `WARN … stop requested by SIGTERM`, which reads as a fault. A stop asked for by a signal, a Windows console event or the RPC's `stop_daemon` is now an IG-14 announcement: `stop requested by <cause>` on standard error and in the log whatever the log level, with no level tag. The line is queued on the log sinks, so the stop does not wait on one, and the closing flush still delivers it. A forced stop (chain sync's owner ending on its own) is an error line, `chain sync stopped: <cause>; the daemon stops`, and it fails the exit. The cause is a type (`StopCause`); a forced stop carries the owner's `EndCause`, so the line can no longer read "a stop" when the cause was lost.
