- **RPC channel: a client key holds at most four sessions** (`RPC_CHANNEL.md` RT-W11, RT-O37). The daemon's session index counted no sessions per key, so one compromised enrolled key on the operator's network could hold every connection the daemon admits and lock its administrator out of revoking it. `SESSIONS_PER_CLIENT` (4, `shekyl-rpc-channel`, an Assumption: five clients fit in `rpc-connections-max`'s default of 25 with five to spare, and the console's four are its own) is read where a session joins the index, under its lock; the session past it is answered `OverResourceBound`, `bound.sessions`, on its first request, then closed, and the node logs the fingerprint. `CORE_RPC_VERSION` 4.7. The owner-only file rule the daemon's key files follow moves to `shekyl-os-account` (`private_file`), where the tunnel and a CLI on another host will write their keys under it, and the service record's path is composed by one function in `shekyl-rpc-rendezvous` (`service_record_path`). The daemon's channel idle stays one hour.
