- **The mempool tests and the Tor transit spike own their temp directories.** `shekyl-mempool`'s pool tests opened their files at a hand-built path under the system temp directory and removed only the `.redb`, so every run left the store's `.creation-lock` behind; they now take a `TestPath` (a `tempfile` directory holding the pool file), as the chain-store and chain-ingest tests do, removed when the test ends, a panicking test included. An evict fixture holds the pool and that directory in one value, the pool field first, so the pool closes before the directory is removed. The transit spike removes its tor data directory only when the session returns success, and keeps it, with the path printed, when the session returns an error. A panic aborts and a signal ends the process; neither runs that removal, so the directory stays for diagnosis.
