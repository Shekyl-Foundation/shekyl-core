- **P2P and relay: three log lines no longer report a fault where there is none** (the alpha.11 hunt, rows 1–3; `P2P_3_SLICE_3_DIALER_BRIEF.md` "An idle connector" and "Recovery", `DAEMON_RELAY_PRIVACY.md` §98.5). **The dialer's idle line** was a warning every hour on every public seed of the 16-node testnet, whose clearnet target of twelve it can never reach. A draw re-armed it, so a dead address thawing on the cooldown ladder brought it back, and it named cooling seats and a dial in flight below the bound "a filter holds every address". It is now an info line, said once per reason per under-target spell, naming the sessions held, the target and the reason: a dial in flight, a retry waiting, no fill rule taking the drawable addresses, no address, the unused addresses cooling after a failed dial or held by an excusal, or every address connected, on a reached host or the node's own. **The recovery episode** read the `Keep` count, which counts dials in flight, so every `Keep` draw closed it as "a kept session was added" and the draw's failure reopened it (a pair every ~16 s in CS-5's fleet run), and a draw of an address it had not re-admitted closed it too. It now counts sessions held and ends only on a gained session or a met target. **The stem fallback** logged `unable to send transaction(s) via Dandelion++ stem` at ERROR for every stem a node with no outbound session holds, and also when the refresh had merely turned the epoch to fluff. The fallback is the designed retry-then-fluff; the line is debug and names why. A retry that ever answered "no address-hiding edge" now holds the origin instead of fluffing it. **The address-hiding class lines** (`hop-0 edge cannot rotate`, and the empty class) are info lines: Tor churn takes a NAT node through both on its way back. The warning moves to where the consequence lands: the relay warns when it holds a transaction this node originates and names the hold (no address-hiding session, or a session is up and this origin's pin is exhausted for the epoch). With operator-run Tor the empty class was said only at debug.
