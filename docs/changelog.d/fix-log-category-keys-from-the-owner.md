- **A `log-category` key a binary writes nothing under is refused.** Each binary's `log-category` takes only the subsystems its own code and its dependencies log under: `shekyld` takes `daemon`, `p2p`, `sync`, `chain`, `txpool`, `relay`, `rpc`, `tor`, `miner` and `notify`; `shekyl-cli` takes `daemon`, `p2p`, `chain`, `rpc` and `wallet`; `shekyl-wallet-rpc` takes `daemon`, `chain`, `rpc` and `wallet`; `shekyl-rpc-tunnel` takes `daemon` and `rpc`. A dead key, such as `wallet` on `shekyld`, was accepted and changed nothing; it is now refused (`config.value.key-not-taken`), naming the binary and listing the keys it takes. Any other word is refused as before (`config.value.word`), now listing the same keys.
- **Every line a binary writes falls under a `log-category` key.** The pool's lines log under `txpool`, and the miner's, the proof checks' and the RPC tunnel's under `miner`, `chain` and `rpc`. Before, those lines fell under no key, so no `log-category` setting reached them.
