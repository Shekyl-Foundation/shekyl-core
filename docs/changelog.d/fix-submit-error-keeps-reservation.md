- **A failed submit says whether the reservation is kept.** `SubmitError::keeps_reservation` in `shekyl-engine-core` answers, from each arm's documented lifecycle, whether the engine still holds the reservation (`consumer_held` or `in_flight`, with its output locks). The match is exhaustive, so a variant added later does not compile until its answer is written; a test pins the answer for all ten arms. A consumer outside the crate cannot match the `#[non_exhaustive]` enum exhaustively: the GUI wallet's own `matches!` read every arm it did not name as released, and discarded four reservations the engine keeps (`DispatchNotSaved`, `SnapshotInvalidated`, `ReanchorUnavailable`, `ReselectionRequired`). The GUI now asks this method.
