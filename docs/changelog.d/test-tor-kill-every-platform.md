- **The Tor live tests that kill Tor now run on Windows and macOS too** (`tor-pin-verify`, `TOR_SUPERVISOR.md` §7).
  - **How Tor is killed.** One test helper, `shekyl-tor-control-client` `outside_kill::kill_tor_named_by`, kills a managed Tor from outside. The process must be named `tor` (`tor.exe` on Windows), and its command line must contain the test's data directory as text: `pkill -9 -f` on Unix, with the path escaped so it is not a regular expression, and `Stop-Process -Force` on Windows. Nothing killed is `pkill`'s exit 1 on Unix, and on Windows the script's exit 3, a status PowerShell never gives by itself. Any other failure of the tool or the script, a failed process query among them, panics. The `Windows (MSVC, daemon)` job now runs the helper's three tests, which no Windows lane ran before.
  - **Wallet tests.** The wallet's three respawn tests (crash and respawn, the onion republished on every incarnation, the degraded episode) were `#[cfg(unix)]` and now run on Windows. The fourth, the bootstrap-timeout restart, does not kill Tor and is required by name with them.
  - **Daemon tests.** The daemon's death-watcher and probe-respawn tests were Linux-only and now run on Windows and macOS. The death watcher expects the exit code `outside_kill::reaped_exit_code` reports: none after a signal, `-1` after `TerminateProcess`.
  - **Workflow.** The four wallet live tests and the five daemon live tests are each one list, required by name on every `tor-pin-verify` entry. A platform that cannot run a test leaves it off that entry's own list. These two sets have no such test.
  - **Descriptor-inheritance gate.** `check_spawn_children_inherit_stdio_only.py` treats a spawn as test-only when its `cfg` is false in a shipped build, with `test` and `unpinned-tor-for-tests` off and every other option unknown, so `outside_kill`'s `any(test, feature = "unpinned-tor-for-tests")` is exempt and `any(unix, feature = "unpinned-tor-for-tests")` is checked. A `cfg` the gate cannot read is checked.
