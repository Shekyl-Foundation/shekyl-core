- **The chain store runs on redb 4.6, and an unsound dependency fails the audit.** redb 4.6 stops a repair from opening a damaged store as an empty one, refuses to commit a transaction whose table was leaked, and makes closing a database wait for the reads and writes in progress; the file format is unchanged. The store creates its files through `create_with_backend`, the body of the deprecated `create_file`. postcard is built without `heapless-cas` and imageproc 0.27 without its defaults, which takes heapless 0.7 (nine unsound advisories, RUSTSEC-2026-0574..0582), paste, ttf-parser and atomic-polyfill out of every lock (the maintained `pastey` comes in as a build-time macro); the shard rasters are pixel-identical. The workspace and fuzz locks are refreshed (rustix 1.1.6 clears RUSTSEC-2026-0486). `cargo audit` fails on an "unsound" advisory as it does on a vulnerability, and its three discharged "unmaintained" ignores are gone.
- **Every package on a proving, signing, wiping, RNG or seed path is held at a reviewed version.** `rust/.cargo/crypto-closure.toml` records the 114 packages of that closure, each with the version core's test vectors, KATs and constant-time harness ran against and the reason it is there. `scripts/ci/check_crypto_closure.py` fails when the workspace lock, a fuzz lock or the GUI wallet's lock carries one of them at another version, and when the closure gains or loses a package without the record. Moving a version in the record is a review.
- **Core's lock is the authority for every package the GUI wallet shares with it.** `scripts/ci/check_gui_lock_shared.py` fails, naming the package and both locks, when the wallet's lock carries a shared package at a version core's lock does not.
- **Configuration and prefs files are TOML 1.1.** `shekyld`'s, `shekyl-cli`'s and `shekyl-wallet-rpc`'s config files, the wallet's `prefs.toml`, and the chain forge's plans and pins are read with toml 1.2. A file may now put newlines and a trailing comma in an inline table, use the `\e` and `\xHH` escapes, and write a time without seconds; the key grammar is unchanged, and a key nothing declares is still refused by name. Most parse errors read as before. Three read differently: a repeated key says `duplicate key` (the line is named; the config diagnostic no longer repeats the key, because it never echoes file text, which may be a secret), a missing value says `string values must be quoted`, and an unquoted word such as `four` says `invalid boolean, expected false`. Files the wallet writes are byte-identical.
