- **The Tor status has one shape and one set of words** (`TOR_STATUS_CRATE.md`; `INPUT_GRAMMAR.md` §23, Part G). The new crate `shekyl-tor-status` holds the Tor status as it will cross RPC, and the one function that turns it into sentences. The daemon's log now says what that function says, so the log, `shekyl-cli` and the GUI wallet will say the same thing once the status is on the wire (#1347). A reply carrying a value this build does not know still reads, and says once that the program should be updated. Such a value never reads as Tor hiding the node's address, so the send flow holds the transaction instead of sending it. The node's log also names the Tor file that failed its check.
