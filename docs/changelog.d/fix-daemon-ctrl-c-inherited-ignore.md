- **A node started with Ctrl-C ignored keeps it ignored, and says how to stop it** (ruled 2026-11-08). A program started in the background, by a shell's `&`, `nohup` or Windows' `start /b`, is asked to ignore an interrupt so that Ctrl-C at the terminal leaves it alone. On Linux, FreeBSD and macOS `shekyld` now reads that at start: when `SIGINT` is ignored it stays ignored, and the start says "Ctrl-C is off because the program that started this node asked for it. Stop it with SIGTERM or the service stop." Before, the daemon took `SIGINT` anyway. Windows already honoured the request, and gives a program no documented way to read it, so every Windows start now names the stops that always work: Ctrl-Break and closing the window.
