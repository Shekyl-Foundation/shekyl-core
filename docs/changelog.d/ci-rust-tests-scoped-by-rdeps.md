- **The Rust job runs the tests a change can reach.** The change-scope job names the changed workspace packages, and the Rust job runs their tests and those of every package that depends on them (nextest `rdeps()`, dev-dependencies included), with the doctests cut to the same closure; the build stays the whole workspace, so each crate compiles with the full run's features. A change to an input every crate shares (the workspace manifest and lock, the toolchain, the cargo and nextest configuration, `config/`, the job's own workflow, the classifier) runs everything, as does any path nothing claims or any error. A change under `scripts/ci/` or `.github/` is owned by the jobs that run it (`scripts/ci/job_owners.tsv`, held to the tree by the classifier's selftest): a change to a documentation gate or another workflow's job skips the Rust job, and a change to a script the Rust job runs runs the job's gate steps with no test. The push to `dev` is unchanged: its base is the last green run, and a change the classifier cannot place runs everything.
