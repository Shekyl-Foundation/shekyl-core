- **One typed transaction key (R-21, `SECRET_STORAGE.md` SSR-Q3).** `shekyl_crypto_pq::TxKey` is the transaction key `r` every output is built from: a canonical scalar behind a pointer, wiped on drop, never cloned or printed, with no accessor for its bytes. It is made in one place, by `TxKey::random` (every wallet-built transaction and the node's coinbase template), `TxKey::from_genesis_seed` (the genesis tool, same bytes as before, pinned by the genesis KAT) or `TxKey::seeded` (only under the TEST_ONLY `seeded-rng` feature). It gives `R`, and every output constructor and the encapsulation re-derivation take `&TxKey`; no transaction-key byte parameter is left in the crate's public API. The wallet keeps a `StoredTxKey` for later OUTBOUND proofs (the record's bytes are unchanged) and opens it with `TxKey::open`; an OUTBOUND proof publishes a `DisclosedTxKey`, which its verifier reads back. A failed OS random draw is a named error where the wallet used to panic (a send reports it as `-29119 SIGNER_FAILED` with `data.fault` `randomness`), and the template keeps its typed refusal. The claim's `TxKeyDraw`, the block template's and the genesis tool's `tx_pubkey`, and `generate_tx_key` are deleted; the rule-36 inventory loses its transaction-key rows. The harness wallet's fixture coinbase sits behind its own TEST_ONLY `seeded-rng` feature.
