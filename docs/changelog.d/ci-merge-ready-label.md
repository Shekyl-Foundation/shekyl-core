- **A pull request merges on its owner's `merge-ready` label, which GitHub holds to the head** (ruled 2026-11-19). Pull requests were merged when the required checks went green while other workflows and fleet runs on the same head were still going. The owning lane now applies the `merge-ready` label when every check on the current head has concluded, its fleet and local runs are done and its review threads are resolved. `merge-ready.yml` keeps a commit status of the same name: pending without the label; success when the label stands; refused, with the label taken off and a comment naming each reason, while any check runs or is red, a review thread is open or the pull request is a draft; and back to pending when a push takes the label off, with a comment. The label is a signal to the merger and runs no test (ruled 2026-11-23). It is a status rather than a job, so it can never be skipped into a pass (`scripts/ci/merge_ready.py`).
