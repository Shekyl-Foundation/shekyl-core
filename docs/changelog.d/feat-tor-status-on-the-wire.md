- **The node's Tor status reaches its RPC and `shekyl-cli status`** (`CORE_RPC_VERSION` 4.2; `INPUT_GRAMMAR.md` §23). Every caller can see whether a session that hides the node's address exists. A caller allowed to see the node's status also gets how Tor is set up, what happens to the node's own transactions, and what the managed Tor is doing and why. `shekyl-cli status` ends with the same sentence the node's log says. The data directory's path is shown only to a connection allowed to see the configuration, with any control characters removed. A client that meets a Tor value newer than itself still reads the reply, says once that it should be updated, and never treats that value as hiding the node's address.
