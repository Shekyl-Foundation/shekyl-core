- **Benchmarks: the daemon's block path is gated on every pull request.** Until now eleven of the twelve gated instruction-count rows were wallet, signing or serve rows, and no store, validator or proof-of-work path had one. Two rows join the capture (`scripts/bench/capture_rust_baseline.sh`). `shekyl-chain-ingest`'s `block_path_iai` counts the three calls the connector makes for a block, each on its own: `form` (every listed transaction's form, signatures and membership proof, then the block's range proofs as one batch, the verifier's term of `PB-D1`), `validate` with `connect` and the commit at production durability (the store's term, `PB-D1s`), and one pop; and three store reads (a block by height, a run of headers, a run of curve-tree leaves). `shekyl-pow-randomx`'s `verify_header_iai` counts one header's proof-of-work over a prepared cache. The blocks are committed fixtures: chains the scenario driver mined, every spend built by the harness spender and admitted by the validator, at three of the shapes of `DAEMON_REDB_STORE.md` §1.3a.7 (the smallest spend, the input cap, the output cap). A default-lane test replays every fixture, so a consensus change that refuses one fails by fixture name, and the writer is an `#[ignore]`d test the nightly lane lists and never runs. Each shape has a block of four transactions, which the per-PR rows count, and a block at the weight limit, whose rows (`block_path_full_iai`) are the `dev` capture's: forming the 45 spends of the smallest shape is 17.1 billion instructions and about twenty minutes of callgrind a row. The measurement ledger gains `[[gated_row]]`, which names the path set each gated bench counts and is held to the capture script by the ledger check. Owed in this line: the bond-post and emission-claim shapes, and the multisig container once a builder makes one.
