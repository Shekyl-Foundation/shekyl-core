- **Wallets and `shekyl-cli` reach "this computer" on its own leg, never a plaintext port** (RT-W10 step 5; Rick, 2026-11-13 and 2026-11-17). With no `daemon-address`, `shekyl-wallet-rpc`, the CLI's wallet session and its daemon words reach the node this account runs on its owner's socket or pipe, where the peer is checked on every dial; a named address stays plaintext HTTP until RT-W12. One target, never a fallback. A failed peer check is its own failure, never retried: `-29213 DAEMON_PEER_CHECK_FAILED` for a wallet, its own error in the CLI. A wallet beside a node run as a service reads the service's rendezvous record only to say so: `-29214 DAEMON_IS_A_SERVICE` names the service's view listener as the `daemon-address` to set, or says it has none (`rpc-view-listen`). `docs/api/wallet_rpc.yaml` is 0.20.0; `--proxy` without `--daemon-address` is refused. The CLI's daemon words take the enrollment words' resolver: a service's console leg when one runs here, otherwise the owner's leg. The staking legs follow the wallet's target, so a claim, serving start and unstake no longer post to the plaintext listener.
- **Each network names a view port, its RPC port plus one** (11030, 12030, 13030, 14030): `rpc-view-listen` given an address alone binds there. **A service always publishes its rendezvous record** (format 2), naming its channel and its view listener only when each is on; a start announces what it names.
- **The posture's remainder:** a refused network bind names the authenticated channel as the remote leg; the Dockerfile's command uses today's options (no admin listener, the view listener, the owner's socket in a named directory); `DAEMON_RPC_RUST.md` describes grants, the view listener and the channel in place of restricted mode; `RPC_CHANNEL.md` §11.2 keeps only the two rows still true (RT-W12's `https://` arm, RT-W14's Task Scheduler guidance).
- **The log never names a stem's transactions or its successor, at any level** (`RPC_CHANNEL.md` §6.4, RT-O9.3). Debug events that did (the carrier's discarded stem, the stem forward and the embargo's reshape, a failed stem batch, and the template's evicted-entry list) log counts; `shekyl-relay/tests/stem_logs.rs` captures every event at TRACE and checks it.
