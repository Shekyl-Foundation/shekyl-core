- **Gate: the domain-binding gate holds the function that applies the constant.** An `input:<type>` row is proven only when every production function that applies its domain constant takes that type: a parameter, a typed binding, a field of those types, a same-file callee, or another method of the same type. A typed parameter elsewhere in the file does not clear the row. A slice, a `Vec`, an array and a tuple of the type all count.
- **FFI: `shekyl_pqc_sign` refuses a message that is not a signing payload hash.** Both sign exports parse the message as a `SigningPayloadHash` (its `LEN`, 64 bytes) before signing, and a different length fails closed, the refusal `shekyl_pqc_verify` already reports as a parse (`PqcVerifyError::DeserializationFailed`). The domain stays in the Rust function the export calls.
- **A hash or signature bound to the network through its input takes that input by type** (`NETWORK_IDENTITY.md` §2.4.1; `DOMAIN_BINDING_RATCHET.tsv`). The archival draws, challenge nonces, challenge leaf and fire, and settlement selection take the block hash as `BlockHash`; the chain digest takes `BlockHash`, `KeyImage` and `CurveTreeRoot`; the output handle takes `TxHash`; the FCMP++ prove and verify, both SALs and FROST take `CurveTreeRoot` and `TxSignableHash`; and each input's hybrid signature, single and multisig, is verified over a `SigningPayloadHash`. No hashed or signed byte changes. The ratchet's `input-raw` section goes from 35 rows to 17, and the binding gate counts a slice of the type as taking it. The wallet's reorg window and tip hash are `BlockHash` (`LEDGER_BLOCK_VERSION` **12 → 13**, paired `WALLET_LEDGER_FORMAT_VERSION` **22 → 23**). The postcard bytes are identical; the schema type-name change still bumps, so a ledger an earlier build wrote is refused, not migrated. `shekyl_pqc_verify` refuses a message that is not 64 bytes as a parse failure (11).
