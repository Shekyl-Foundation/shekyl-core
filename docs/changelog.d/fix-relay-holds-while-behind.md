- **Relay: a transaction that arrives while the node is catching up to a new block is no longer thrown away** (`DAEMON_RELAY_PRIVACY.md` §101). A node counts as not synchronised from the moment it hears of a block until it has connected it, and in that gap the relay ignored every transaction batch it received. A transaction still on its private stem was lost there with nothing to tell the sender, who then waited out the whole embargo, minutes, before sending it again. The relay now keeps what arrives in the gap and handles it as soon as the node is synchronised. The amount kept is bounded for each connection at what one transaction message may carry, and a connection that closes takes what it had kept with it.
- **Relay: a peer that was given a transaction can no longer cancel the sender's fallback by sending it back late** (`DAEMON_RELAY_PRIVACY.md` §102). When a transaction's private stem gets no sign of having spread, the node sends it once more to a second peer and, failing that too, broadcasts it itself. The node already ignored the transaction coming back from the peer it was currently waiting on. It did not remember the first peer once it had moved on to the second, so the first peer could drop the transaction, wait, and send it back to switch the fallback broadcast off. The node now ignores the transaction coming back from either peer it gave it to.
