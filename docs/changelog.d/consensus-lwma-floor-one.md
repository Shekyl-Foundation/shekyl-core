- **Consensus: LWMA-1 never returns a difficulty of zero; its floor is one** (`DAA_LWMA1.md` §5.3 step 10; Rick, 2026-11-07). A difficulty is the expected number of hashes per block, and a block costs at least one hash, so one is the least difficulty there is. Before this change, a chain whose blocks came slowly enough for long enough derived a next difficulty of zero: with every solve time at the six-target clamp, the formula is zero once the window's average difficulty is six or less. The validator then refused that block and, with it, every block after it, so the chain could never mine again. Now that block's difficulty is one, and the chain recovers: at one every hash is a block, the solve times collapse, and a window of fast blocks lifts the difficulty about tenfold. Every difficulty above zero is unchanged. `shekyl_difficulty::Difficulty` is non-zero by construction, so no code path can build a zero target. The census's CEN-D6 is held by that type, and the validator's zero refusal is gone, along with what only it produced: the target claim's refusal in chain sync and ingest, and the template reason `target_refused` under `mine.unbuilt`, which nothing can produce any more. This departs from canonical zawy12 LWMA-1, which has no floor. New spec vectors 8 and 9 pin the floor and the climb, and zawy12's reference oracle checks both: on vector 8 it returns zero where Shekyl returns one, and with step 10 applied it agrees. A nightly test, `a_chain_at_the_difficulty_floor_mines_its_way_back`, mines real RandomX blocks from a window of ones back above one hundred.
