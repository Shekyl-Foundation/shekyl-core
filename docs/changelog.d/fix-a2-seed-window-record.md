- **Daemon: the previous epoch's RandomX cache is released once the seed window stops naming it** (alpha.11 bug hunt A2; Rick, 2026-11-09). The release #1301 added never fired on a running node: after the epoch switch every connected block re-pins the same canonical seed, which moves no cache slot, but the ingest's record of the slots then said the second slot was empty while it still held the previous seed's 256 MiB cache. When the window later stopped naming that seed, the install found its pair already recorded and skipped the release, so the cache stayed resident until the next epoch's pin, about 62% of each epoch (two caches at tip 2,840 on regtest, 2026-11-09). The record now follows the cache store's own slot rules on every pin, preparation and release, and is written under the same lock as the change it records, so the seeds an arrival or a block template may hash under are the seeds the slots hold. The install skips only when the window last installed and the record both equal the window.
