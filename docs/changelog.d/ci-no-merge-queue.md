- **CI: every merge to `dev` is tested where it lands, now that `dev` has no merge queue** (`06-branching.mdc`, "The runs on `dev` test the merge result"). The build matrix and the Rust suite ran on pull requests and on pushes to `main` only, so two pull requests each green alone could merge broken together and show red first on some later, unrelated pull request. Both now also run on every push to `dev`, as do the documentation, doc-claims, FFI-signature, GF-7 and aarch64 KAT gates, each with its pull-request path filter. A burst of merges is tested once, at its newest commit: each push cancels the run before it, and the build and Rust scope jobs measure a push from the last commit that workflow passed on (`scripts/ci/push_scope_base.sh`), so a docs-only merge cannot skip the code merged before it. The queue's `merge_group` triggers and the steps that read them are gone from every workflow.
