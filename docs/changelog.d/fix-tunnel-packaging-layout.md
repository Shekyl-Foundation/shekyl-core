- **The packaged RPC tunnel can make its key and read its configuration** (`RPC_CHANNEL.md` §8; Rick, 2026-11-21; found deploying alpha.12). The unit's own setup step, `--rpc-key-create`, was refused on every packaged host: the tunnel read its account's home before its arguments, and the account `shekyl-tunnel` has none. It now reads the home only for a default path, and a default it cannot have is refused naming the option to give. The unit read its configuration from `/etc/shekyl`, which is the daemon's group's alone, so the tunnel could not read it. The `.deb` and `.rpm` now declare the account `shekyl-tunnel` (`shekyl.sysusers`: no home, no login, never in the daemon's group), refuse to install over a login of that name as they do for `shekyl`, and make `/etc/shekyl-tunnel` `root:shekyl-tunnel` `0750` (`shekyl.tmpfiles`); the configuration and the node's bundle live there as `root:shekyl-tunnel` `0640`, and the unit reads its configuration there. On FreeBSD the rc.d script makes `/usr/local/etc/shekyl` `root:shekyl-tunnel` `0750` before every start. A host set up by hand before this release moves its tunnel's configuration and bundle to `/etc/shekyl-tunnel`.
