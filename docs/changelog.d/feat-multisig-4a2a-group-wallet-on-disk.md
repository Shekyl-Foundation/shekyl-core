- **Existing solo wallets must be restored from their seed.** The wallet ledger moves to format 27 and the send journal to version 7, because a send can now pay a multisig group (below). The version check is an exact match, so a wallet written by an earlier build is refused with the error that names the remedy: restore it from its seed. Its keys, seed and address are unchanged; what the restore does not bring back is the wallet's own record of its sends (who was paid, notes, the keys an outbound proof needs). Before genesis no wallet file is migrated.
- **A solo wallet pays a multisig group.** A send's recipient can be a group, its address read from the group's address file. The fee is priced at the transaction's real weight, which counts the group output's entry of one ciphertext per member; before, the wallet priced only solo shapes and would have underpaid. The send journal names the group by its address's fingerprint and stores the group's address once, however many sends pay it, so the wallet shows who was paid and keeps what an outbound proof needs. A group on another network, and a payment request answered to a group (whose output always carries the sentinel label), are refused before any coin is selected. This is the engine's half of the designed multisig (E′); no command line, RPC or GUI surface offers multisig, and whether it is offered is decided once E′ is complete.
- **An output's position in a transaction is a type.** Output construction takes an `OutputPosition`, which carries the transaction key and the index together; production code gets positions only from the transaction key's order, all outputs at once. The three block producers name their fixed position through one constructor, and a gate allows only them. Two outputs on one index, a made-up index and a position used with another key no longer compile.
- **A group wallet keeps its own records on disk.** A group member's scan records group coins and the outputs it refused in a ledger of their own, separate from the solo ledger and its version. An output the group can spend but this member cannot is counted as group funds; one no member can spend counts in no balance. `.wallet.multisig` holds a member's ceremony records (input reservations, its responder approvals, the intent seeds it has seen), sealed beside `.wallet` under the wallet's own key.
