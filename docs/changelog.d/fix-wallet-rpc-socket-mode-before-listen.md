- **Every local socket is its owner's alone from the first moment anything can connect to it** (Rick, 2026-11-22). The wallet RPC server, the daemon's owner socket, the daemon's console leg and the RPC tunnel each bound their socket and then set its mode to 0600, and the bind already accepted connections, so a connect could land while the socket still had the umask's mode (a FreeBSD run under umask 002 found it 0775). They now bind through one function that binds, narrows the socket to 0600, and only then listens; a connect before that is refused. The socket's directory must still be the account's alone in all four: it is what keeps other accounts out on systems that do not enforce a socket's mode on connect.
- **The RPC tunnel's socket is 0600.** It had the umask's mode; its owner-only directory already kept other accounts out, so nothing that could reach it before is refused now.
- **A socket another account owns is never replaced** by any of the four at start; the daemon's owner socket already refused one, and the wallet RPC server and the tunnel now do too, naming its uid.
- **The daemon's data directory is its account's alone; an existing node needs a one-time `chmod 700`** (Rick, 2026-11-22). The data directory holds the daemon's keys, among them a service's console key (`rpc-console.key`, the host's administrator), and the console's socket, and the daemon made it with the umask's mode, often `0755`, which let every account on the host list it. Every directory the daemon creates on its data directory's path, the data home and the network directory included, is now `0700` whatever the umask, and a start refuses an existing data directory other accounts can enter with `config.data-dir.exposed`, naming the directory and the fix. A symbolic link, a non-directory, an unreadable path, or another account's directory is `config.data-dir.unusable`. The daemon never changes a mode it did not set. **Upgrading a node whose data directory was made by an earlier release:** run `chmod 700` on it before the start, as the daemon's account or root, e.g. `chmod 700 /var/db/shekyl/testnet` on a FreeBSD service, or `chmod 700 ~/.shekyl/<network>` for a daemon run as a user. A Linux service under the shipped unit is already `0700` (systemd's `StateDirectoryMode`). The wallet binaries make the per-account root the same way. Windows is unchanged: the keys and the console's pipe there carry owner-only descriptors of their own.
