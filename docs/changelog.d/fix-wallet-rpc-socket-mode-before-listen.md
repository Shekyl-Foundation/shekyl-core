- **Every local socket is its owner's alone from the first moment anything can connect to it** (Rick, 2026-11-22). The wallet RPC server, the daemon's owner socket, the daemon's console leg and the RPC tunnel each bound their socket and then set its mode to 0600, and the bind already accepted connections, so a connect could land while the socket still had the umask's mode (a FreeBSD run under umask 002 found it 0775). They now bind through one function that binds, narrows the socket to 0600, and only then listens; a connect before that is refused. The socket's directory must still be the account's alone in all four: it is what keeps other accounts out on systems that do not enforce a socket's mode on connect.
- **The RPC tunnel's socket is 0600.** It had the umask's mode; its owner-only directory already kept other accounts out, so nothing that could reach it before is refused now.
- **A socket another account owns is never replaced** by any of the four at start; the daemon's owner socket already refused one, and the wallet RPC server and the tunnel now do too, naming its uid.
- **A service's network directory is held to the same fact as its console socket** (Rick, 2026-11-22). The configuration check refuses it when another account can enter it, as the start's console bind does. A set-id bit or the sticky bit is not that refusal. The service's home stays mode `0700` exactly.
- **The daemon's data directory is its account's alone; an existing node needs a one-time `chmod 700`** (Rick, 2026-11-22). The data directory holds the daemon's keys, among them a service's console key (`rpc-console.key`, the host's administrator), and the console's socket, and the daemon made it with the umask's mode, often `0755`, which let every account on the host list it. Every directory the daemon creates on its data directory's path, the data home and the network directory included, is now made `0700`, and a start refuses an existing data directory other accounts can enter with `config.data-dir.exposed`, naming the directory and the fix. A symbolic link, a non-directory, an unreadable path, or another account's directory is `config.data-dir.unusable`. The daemon never changes a mode, new or existing. **Upgrading a node whose data directory was made by an earlier release:** run `chmod 700` on it before the start, as the daemon's account or root, e.g. `chmod 700 /var/db/shekyl/testnet` on a FreeBSD service, or `chmod 700 ~/.shekyl/<network>` for a daemon run as a user. A Linux service under the shipped unit is already `0700` (systemd's `StateDirectoryMode`). The wallet binaries make the per-account root the same way. Windows is unchanged: the keys and the console's pipe there carry owner-only descriptors of their own.
- **A data directory under a directory other accounts can write is now refused, `/tmp` included** (Rick, 2026-11-23). Whoever can write a directory above the data directory could swap it for a link and redirect the daemon's keys. A start now checks every directory above the data directory before it makes or uses anything, and refuses with `config.data-dir.ancestor-writable`, naming the directory and who can write it: any owner but root or the daemon's account, or any group or other write bit, with no exception for a sticky directory. Move the data directory under one only root and its account can write, such as the account's home. A symbolic link on the path is judged at both ends: the directory holding the link and every directory above where it resolves.
- **The configuration file loader is stricter by the same rule.** It already refused a writable directory above the file. It now also follows symbolic links on the path and refuses a writable directory above where one resolves.
- **A umask that removes the owner's own permission refuses the start** (`config.data-dir.umask`, naming the umask's owner digit, such as `02xx`). The daemon no longer changes the mode of anything it creates. The ordinary umasks (`022`, `002`, `027`, `077`) all give a new directory `0700`.
