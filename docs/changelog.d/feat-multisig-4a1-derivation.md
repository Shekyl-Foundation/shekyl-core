- **Every member of a multisig group derives the group's spend from the intent alone (slice 4a-1).** `DerivedSpend::derive` builds the transaction a ceremony signs from the validated intent, the member's ledger (`GroupOutputs`, a lookup by global index) and the group's key from the member file. Recipient `i` is output `i`, built by the one output builder every spend uses (`shekyl_tx_builder::outputs`, which now pays a single-signer address or a group and converts the view key itself), under the transaction key the intent's seed derives. Each input's pseudo-out blind and rerandomization seed come from the same seed (R-14, `PQC_MULTISIG.md` §9.5), with vectors written and checked by an independent stdlib oracle. A ledger record (`GroupOutput`) holds no secret: each input's `x`, `y_kem`, `z` and leaf blind are re-derived from its `0x06` ciphertext in `shekyl-crypto-pq` (`recover_group_spend`) and checked against the record's key image, leaf point and path, each mismatch refused by name. A context is built from the derived spend alone, and the proposer proves from its own context. Intent v3 names each recipient's kind (a single-signer address and its label block, or a group's payload), refuses an input listed twice, and refuses a single-signer address not written as the one string it encodes to (R-22). The intent's seed is a `shekyl-crypto-pq` type that never hands out its bytes, and the replay set holds its fingerprint, never the seed. Held nonces live in memory only (R-20): the nonce counter, its sink, `Proposer::resume` and `Holder::committed` are deleted, and a wallet closed mid-ceremony forfeits its part. `shekyl-tx-weight` prices any spend by its signer, solo or group, and the groups it pays (`predict_spend_weight`), exact against real 2-of-3 and 3-of-5 spends.
