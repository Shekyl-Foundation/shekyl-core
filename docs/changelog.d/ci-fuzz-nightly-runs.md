- **CI: every fuzz target is run every night, and four of them for thirty minutes every week.** The nightly workflow gains a `fuzz` job: every fuzz target in the tree (37, listed by `scripts/ci/check_fuzz_inventory.py --targets`, so the list cannot drift from the crates) runs for five minutes on a pinned nightly toolchain, from a corpus cached per target and the target's committed `fuzz/seeds/<target>/`. A leg is green only when it proves it fuzzed (`scripts/ci/fuzz_run.py`): no crash, at least 1,000 executions, a non-empty corpus and the committed lockfile untouched. A crash uploads its input as an artifact, and each red target opens or threads its own nightly-red issue. On Sundays a `fuzz-weekly` job runs the Noise handshake's reader, transaction decode, block decode and KEM decapsulation for thirty minutes each under the same rule. A `fuzz-summary` job tabulates every leg's executions and refuses a run in which a leg reported nothing. New committed seeds: the KEM KAT ciphertexts for `fuzz_kem_decapsulate` and the multisig vector's adversarial blobs for the key and signature blob targets; the inventory refuses a seed directory named for no target.
