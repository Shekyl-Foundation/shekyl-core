- **CI: every fuzz target is run every night, and five of them for thirty minutes every week.** The fuzz lanes are their own workflow (`.github/workflows/fuzz-nightly.yml`, 15:17 UTC, twelve hours from the 03:00 jobs so the two never share the runners): a `fuzz-build` job builds each fuzz crate once on a pinned nightly toolchain, with the address sanitizer, and hands its binaries to the crate's legs; a `fuzz` job runs every fuzz target in the tree (37, chosen by `scripts/ci/check_fuzz_inventory.py --plan`, so the list cannot drift from the crates) for five minutes, from a corpus cached per target and the target's committed `fuzz/seeds/<target>/`. A build is red when it fails or rewrites the crate's committed lockfile. A leg is green only when it proves it fuzzed (`scripts/ci/fuzz_run.py`): no crash, at least 1,000 executions and a non-empty corpus. A crash uploads its input as an artifact, and each red target opens or threads its own nightly-red issue, which links that input. The inventory check holds that workflow to the two crons its planner runs. Later jobs check out the commit the plan recorded, and the two run jobs share one action. A floor moves only with its run id, so a rewritten commit does not lower it. The pre-push lockfile check resolves from the pushed tree's `rust/` directory, where the toolchain pin lives. On Sundays at 19:17 UTC a `fuzz-weekly` job runs the Noise handshake's reader, transaction decode, block decode, KEM decapsulation and the Bulletproofs+ round trip for thirty minutes each under the same rule. A `fuzz-summary` job tabulates every leg's executions and refuses a run in which a leg reported nothing. New committed seeds: the KEM KAT ciphertexts for `fuzz_kem_decapsulate` and the multisig vector's adversarial blobs for the key and signature blob targets; the inventory refuses a seed directory named for no target.
- **Fuzz: three harnesses that had never run are fixed by their first run.** `fuzz_bp_plus_masks` handed the verifier `8·C` where it reads the commitment as carried, so every proof it made failed to verify; it now passes `C`. `fuzz_bech32m_address_decode` sliced its input at byte-length thirds and panicked when a third fell inside a multi-byte character; it now cuts at the nearest character boundary. `fuzz_read_message1` never got past the responder's length check, because unseeded the fuzzer never builds a 1,216-byte input; it is seeded with the pinned message 1 (`kat_m1.hex`). Both crash inputs join their targets' regression corpora.
- **Fuzz: four of the five targets that ran millions of inputs without reaching their code now reach it.** `fuzz_multisig_sig_blob`, `fuzz_body_hybrid_sig_decode` and `fuzz_body_commitment_decode` are seeded with well-formed inputs built from the hybrid-signature KAT, and `fuzz_construct_output_malformed_kem` from the scan-output KAT; that harness also held a spend key that is not a point (`[0x42; 32]`), so every input was refused before the KEM key was read, and now uses the Ed25519 base point. `fuzz_block_header_tree_root` handed the prover a fixed output key that is not a point, so it proved nothing for any input; it is rebuilt to fuzz the verifier over one real proof, built once from a seeded key and blinds, with the fuzzer driving the root, the depth, the hash, the key images and the proof's bytes (about 6,000 executions in five minutes on a runner, so it stays nightly). `fuzz_body_responder_share_decode`, whose cold runs reached the key parser by luck or not at all (coverage 104 once, 57 twice), is seeded with the hybrid KAT key. The three multisig decoders with the lowest coverage are seeded with one whole body each: `fuzz_envelope_v2_decode` (coverage 31) with a plaintext carrying `MULTISIG_INTENT_V2`'s fingerprint and intent hash, a signature-share body and the KAT signature; `fuzz_body_final_tx_decode` (77) with one input signed by two KAT keys; `fuzz_body_signature_share_decode` (87) with one share. The weekly long run gains `fuzz_bp_plus_masks`, whose five minutes are a few thousand executions.
- **Fuzz: each target has a coverage floor.** `scripts/ci/fuzz_coverage_floors.tsv` holds one row per target: the final coverage of a cold, seeded five-minute run, the run and commit that measured it, and a second run's coverage. A nightly leg is red when its coverage is under 90% of the floor, or under a wider tolerance (100% less twice the spread) for a target whose two runs differ by more than 5%; a harness that stops at a length check or a refused constant runs millions of inputs over a handful of edges, and only this rule catches it. `check_fuzz_inventory.py --floors`, in the per-PR fuzz workflow, holds one row per target and refuses a floor that moves without the run that measured it. A libFuzzer `slow-unit-*` file is no longer read as a crash input.
- **Hooks: a pre-push check that every fuzz lockfile still resolves.** `scripts/hooks/pre-push` runs `cargo metadata --locked` for every fuzz crate when a push changes a manifest or lockfile under `rust/` (the dropped `bech32` edge of #1399 passed the version check). Install it with the copy line in the hook's header.
