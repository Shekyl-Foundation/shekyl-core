- **CI: every fuzz target is run every night, and five of them for thirty minutes every week.** The nightly workflow gains fuzz lanes on their own schedule (15:17 UTC, twelve hours from the 03:00 jobs so the two never share the runners): a `fuzz-build` job builds each fuzz crate once on a pinned nightly toolchain, with the address sanitizer, and hands its binaries to the crate's legs; a `fuzz` job runs every fuzz target in the tree (37, listed by `scripts/ci/check_fuzz_inventory.py --targets`, so the list cannot drift from the crates) for five minutes, from a corpus cached per target and the target's committed `fuzz/seeds/<target>/`. A build is red when it fails or rewrites the crate's committed lockfile. A leg is green only when it proves it fuzzed (`scripts/ci/fuzz_run.py`): no crash, at least 1,000 executions and a non-empty corpus. A crash uploads its input as an artifact, and each red target opens or threads its own nightly-red issue, which links that input. The inventory check holds the workflow's schedules and the job conditions that choose between them to agree. On Sundays at 19:17 UTC a `fuzz-weekly` job runs the Noise handshake's reader, transaction decode, block decode, KEM decapsulation and the Bulletproofs+ round trip for thirty minutes each under the same rule. A `fuzz-summary` job tabulates every leg's executions and refuses a run in which a leg reported nothing. New committed seeds: the KEM KAT ciphertexts for `fuzz_kem_decapsulate` and the multisig vector's adversarial blobs for the key and signature blob targets; the inventory refuses a seed directory named for no target.
- **Fuzz: three harnesses that had never run are fixed by their first run.** `fuzz_bp_plus_masks` handed the verifier `8·C` where it reads the commitment as carried, so every proof it made failed to verify; it now passes `C`. `fuzz_bech32m_address_decode` sliced its input at byte-length thirds and panicked when a third fell inside a multi-byte character; it now cuts at the nearest character boundary. `fuzz_read_message1` never got past the responder's length check, because unseeded the fuzzer never builds a 1,216-byte input; it is seeded with the pinned message 1 (`kat_m1.hex`). Both crash inputs join their targets' regression corpora.
- **Fuzz: four of the five targets that ran millions of inputs without reaching their code now reach it.** `fuzz_multisig_sig_blob`, `fuzz_body_hybrid_sig_decode` and `fuzz_body_commitment_decode` are seeded with well-formed inputs built from the hybrid-signature KAT, and `fuzz_construct_output_malformed_kem` from the scan-output KAT; that harness also held a spend key that is not a point (`[0x42; 32]`), so every input was refused before the KEM key was read, and now uses the Ed25519 base point. `fuzz_block_header_tree_root` hands the prover a fixed output key that is not a point, so it proves nothing for any input; it is unchanged pending a ruling on rebuilding it. The weekly long run gains `fuzz_bp_plus_masks`, whose five minutes are a few thousand executions.
