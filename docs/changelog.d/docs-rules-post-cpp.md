- **Rules 35, 36, 45 and 93 state the tree without C++** (ruled 2026-11-08). Rule 36 is a Rust rule: secret key bytes, and material derived from them, are clamped, reduced, hashed and combined only in the crypto-owning crates, and every other crate passes typed values. A new gate, `scripts/ci/check_secret_byte_locality.py`, replaces the deleted C++ clamp lint: it scans every production `.rs` file outside those crates for the clamp on byte 0 or 31 and for a scalar reduction whose argument names a secret, and holds the twelve sites that exist today to `docs/ci/secret-byte-locality.tsv` in both directions, each with its reason (the transaction key reduced for `R = r·G` in five places, the spend secret combined into `x = ho + b` in two, the genesis tool's two, and Tor's onion-identity clamp). Rule 45 takes rule 25's wording on `unsafe`: every crate root denies `unsafe_code`, and code that calls the operating system or a C library allows it on the item that makes the call, with a `SAFETY` comment. Thirty-five crate roots that hold no `unsafe` now deny it; seven crates that make operating-system or C calls do not yet, and the rule names them. Rule 35 drops its C++ and FFI sections, and rule 93 keeps its lasting part: never introduce a `MONERO_*` identifier, and frozen domain separators stay.
- **Rule 40 is retired** (ruled 2026-11-08). The FFI surface it governed is deleted; its one live sentence, "do not add a C ABI to reach a Rust crate", is in rule 25, and its body is the record `docs/completed/RULE_40_FFI_DISCIPLINE.md`. Rule 35's OS-level section stays a requirement and names its implementation: every binary calls `harden_process` first, and the long-lived secret types in `shekyl-crypto-pq` own locked, dump-excluded storage. That storage, and the move of seven key reductions in wallet and node crates behind typed constructors, are the secrets-storage round (`SECRET_STORAGE.md`, `SSR-`), which lands after the alpha.12 cut; the `unsafe` scoping of five operating-system crates follows it, and rule 45 names the two RandomX C-reference crates as its only crate-level allows. `AllKeysBlob`'s doc no longer claims a C++ `mlock`'d allocation.
- **Rule 25 takes rule 40's decoder sections, re-scoped to every decoder of untrusted bytes** (ruled 2026-11-08): bound a decoded count before it sizes an allocation (the backing bound and a protocol ceiling, whichever is tighter), no crate- or module-wide allow of the cast lints in a decoder, and refuse, never panic, on malformed input. The FFI-only bullets are dropped. The source-scan gate for the reserve rule lands in the `unsafe` scoping PR (`SSR-R2`).
