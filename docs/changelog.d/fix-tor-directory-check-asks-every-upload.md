- **Daemon: the onion's directory check asks every directory its descriptor was sent to, not only those that confirmed** (`TOR_SUPERVISOR.md` §4.5; Rick, 2026-11-15). An upload whose connection fails reports nothing to the control port, so a check that asked only confirmed uploads never asked the directories that may hold nothing. In SO-D12's run 4 an onion read Reachable on the four of its eight current-period directories that confirmed; the other four never reported, the one Tor itself asked never answered, and a peer gave up after 105 s waiting for the onion's descriptor. The check now asks them all. For an upload Tor never confirmed, any answer but this node's own copy counts as missing; for a confirmed one, an answer that says nothing about the copy is still not counted. This node's own failure to ask is never counted. An upload still in flight is asked only once its round is older than the round's wait, so a second probe drawn just after a new round began does not count those uploads missing. A republish the check drives takes the same backoff as any other. Each judged check now says every directory at debug: how its upload ended, what Tor said, and how it counted.
