- **A file the daemon replaces is replaced in one place, and a scanner that holds it is waited for** (`shekyl-os-account`, `shekyl-win-sec`, `shekyld`; Rick, 2026-11-18). On Windows a program that opened a freshly written rendezvous file without delete sharing (an antivirus scanner, a search indexer) failed the start with a sharing violation, blamed the directory with a Unix remedy, and left `shekyl-<name>.<pid>.new` behind for good. `StagedWrite::commit` is now the only place a file is replaced. On Windows it renames through the handle (replace-if-exists, POSIX semantics; the classic rename on FAT32 and exFAT), so a reader of the old file that shares delete does not block it. Removing a leftover staged file, opening the staged file and the rename share one 2 s deadline, waiting for a reader of either file that does not share delete. Past it the start refuses with `config.replace.held-open`, naming the file held and the directory to exclude from scanning. A stale owner's record is replaced by the publish under the same wait, no longer refused as an impostor when a scanner holds it. A staged file's kind is in its type: a journal (the console key) is resumed at a start and never discarded on a failure; a replace (a rendezvous record, the console leg's name, the bundle) is removed by the next start's write and by its own failed commit.
- **Six more crates replace their files through that one replace** (`shekyl-daemon-config`, `shekyl-dialer`, `shekyl-tor-control-wallet`, `shekyl-engine-prefs`, `shekyl-chain-ingest`, `shekyl-engine-file`; Rick, 2026-11-18), and `rust/clippy.toml` refuses `std::fs::rename` and tempfile's `persist` family everywhere else, a rename that is not a replace carrying an allow that names why. No file's protection changes. The data directory's network marker keeps its syncs. The dialer's address file, written before with no sync at all, is now synced before the rename and its directory after. The vanguard state file's staged copy is a journal: a failed save keeps it and the next start recovers the set from it, as it did from the old `.state.tmp`. The wallet preferences pair keeps its owner-only mode and its syncs. A rebaseline trace and a height-digest table publish through one staged name per file, one publisher per path. A wallet file is staged as `<name>.new` and, on Windows, renamed through the handle that supersedes the keys file under a live lock during password rotation, with no `FILE_ATTRIBUTE_TEMPORARY` to clear; `WalletFileError::AtomicWriteFinalizeStaged`, which only that clear produced, is gone. The Tor directory cache is not yet converted: its staged name would be `cached-microdescs.new`, one of the four files it keeps.
- **A refused start is in the log file** (`shekyld`). Every refusal or failure that ends a start reached standard error alone, which a service's operator may never see. It now also reaches the log file once the configuration names one; `--config-verify` still writes nothing.
