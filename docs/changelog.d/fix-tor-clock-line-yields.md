- **A corrected clock no longer hides what still blocks Tor** (`TOR_SUPERVISOR.md` §4.4; follow-up to #1340). Once the operator set the clock right, Tor's earlier clock report went on holding off any other reason Tor could not connect, so the node kept saying the clock was days off and never named the real problem. Tor's own report of the jump is what lets a blocked link be named. The node's check that the clock looks right does not: that check also fires when a consensus ages into range, or when the machine slept, and it does so on every OS. A repeat of the same clock figure in the next minute is a handshake that was already open, and it leaves the new line standing. A later repeat, or a different figure, names the clock again.
