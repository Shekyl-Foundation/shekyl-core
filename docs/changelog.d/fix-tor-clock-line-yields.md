- **A corrected clock no longer hides what still blocks Tor** (`TOR_SUPERVISOR.md` §4.4; follow-up to #1340). Once the operator set the clock right, Tor's earlier clock report went on holding off any other reason Tor could not connect, so the node kept saying the clock was days off and never named the real problem. Once the clock is seen to change (Tor reports the jump, or the node's own check finds it right), a blocked link is named again; if Tor reports the clock off once more, the clock takes the line back.
