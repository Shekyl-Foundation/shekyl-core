- **Daemon RPC 4.1: a reply holds the fields its request selected, and `daemon_status` follows its grants** (Rick, 2026-11-12; `RPC_WIRE.md` RW-Q4 as amended, `RPC_CHANNEL.md` §6.1). **Breaking for every daemon RPC client:** a client refuses a daemon of another version at the version read.
  - **`pow` and `prune` select fields.** A header carries `pow`, a hash and never `null`, exactly when the request asked for it; a header the daemon cannot supply it for is refused. A transaction's entry in `tx_show`, `tx_list`, `block_show` and `block_list` is `{id, body}` with the whole body, and under `prune` the skeleton: the pruned body with `prunable_hash`, `pqc_auth_hash` and `archival_size`. A client refuses a reply that carries a field its request did not select, or lacks one it did.
  - **`daemon_status` by grant.** A caller holding `health` is told whether the node is usable now: the tip, the target, the sync and offline flags, `peered`, the writer, the protocol version and its grants. The chain's facts need `chain`, and `txpool_count` needs `pool`; a caller without the grant finds them absent. The view listener holds both, so a wallet sees no change.
  - **`shekyl-cli`** says which grant a connection lacks when a console word needs a chain fact it is not shown.
- **The daemon serves its owner on a private socket, and stops when it goes** (RT-W10 step 3; `RPC_CHANNEL.md` §7.1; `INPUT_GRAMMAR.md` IG-Q103…IG-Q105, Rick, 2026-11-12). Linux and macOS. **Breaking for daemons run without a login session:** a daemon run as its user now needs a session directory (`/run/user/<uid>` on Linux, the per-user temporary directory on macOS) or a directory named with `--rpc-socket-dir`; without either it refuses to start and names the three ways forward.
  - **The socket.** `<dir>/shekyl-<name>.sock`, named by a hash of the network and the instance, in a directory the daemon asserts is its account's alone (mode 0700, local) rather than adopting it. A connection on it is the host's administrator, with every grant. The start line names the network, the instance and the path.
  - **One daemon per account, network and instance.** A second one dials the first's socket at start and refuses while it answers; a socket nobody answers on is replaced; anything else at the path is reported and left alone.
  - **The daemon's life is its socket's.** The socket is watched every second; when it or its directory goes, the daemon logs why and stops cleanly. A clean stop removes the socket before the RPC drains.
  - **`--instance <name>`** names a deliberate second node of the same network on one machine, with its own `--data-dir`. **`--rpc-socket-dir`** names the socket's directory on a host with no session directory (a CI runner, a container); every regtest harness in the tree now names one per daemon.
  - **`--service` is accepted on Linux and macOS:** the machine's service instance, with no owner's socket and its loopback listeners kept. It needs the service's rendezvous directory, `/run/shekyl` on Linux (the shipped unit's `RuntimeDirectory`, now mode 0755) and `/Library/Application Support/Shekyl` on macOS: the daemon's account's, not a link, not writable by its group or others, and the daemon not root. Otherwise the start refuses and names what failed, so an ordinary account cannot start as the service. The shipped unit passes `--service`. On Windows it waits for the service-manager dispatcher (RT-W14).
