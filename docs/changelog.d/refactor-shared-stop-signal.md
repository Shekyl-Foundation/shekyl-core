- **Every program stops the same way: one stop module, a second stop exits at once, `SIGHUP` is a clean stop** (`DAEMON_CONFIG_CUTOVER.md` §2.2 step 9; Rick, 2026-11-20). `shekyld`, `shekyl-wallet-rpc`, `shekyl-cli` and `shekyl-rpc-tunnel` take their stops from one module in `shekyl-process`; the three copies they had are deleted. On Unix the stops are `SIGTERM`, `SIGINT` and `SIGHUP`; on Windows, every console event. The first is a clean stop. A second stop (`SIGINT`, `SIGTERM` or any Windows console event after the first) now exits at once with status 130 and no cleanup, in every program; a `SIGHUP` never counts as the second, since a closing terminal under bash sends two: the daemon used to ignore a second `SIGTERM` or `SIGINT` on Unix and finish its teardown, and on Windows a second console event ended it through Windows' default handler (`0xC000013A`); the tunnel used to ignore a second stop for up to 11 seconds while its open requests finished. Every program's next start takes over or clears what such an exit leaves, and the systemd units count exit 130 as clean (`SuccessExitStatus=130`), so an operator's forced stop is not restarted. `SIGHUP`, which a closing terminal sends, is now a clean stop for the daemon and the tunnel, which it used to kill (the tunnel leaving its socket file behind); an inherited `SIGHUP` ignore (`nohup`) is kept, silently.
- **The tunnel stops cleanly on Ctrl-Break and when its window closes, on Windows.** It used to take Ctrl-C alone, so Ctrl-Break, a closed window, logoff and shutdown ended it through Windows' default handler with nothing said. On every Windows start the daemon, the wallet RPC and the tunnel now name the stops that always work, naming the program ("Stop shekyl-rpc-tunnel with Ctrl-Break or by closing its window …"); the daemon's line used to say "this node".
- **The wallet RPC server and the tunnel keep Ctrl-C off when the program that started them asked for that** (IG-14). Started with `SIGINT` ignored (a non-interactive background list, `trap "" INT`), they used to take `SIGINT` anyway and stop on it. They now keep the ignore and say once, at start, that Ctrl-C is off and that `SIGTERM` stops them, as the daemon does; `shekyl-cli` does the same on Unix.
- **The wallet RPC server arms its stops before it binds, names stop causes as the daemon does, and never takes over a live socket.** A `SIGTERM` between the bind and the arm used to kill it and leave its socket file; it is now a clean stop that removes the socket. Its log names a cause as `Ctrl-C`, `window close` and `shutdown` (it said `ctrl-c`, `console close`, `system shutdown`). A start on a socket path removed whatever was there, including a socket another server was answering on and a file that was not a socket; it now replaces only a socket whose connection is refused, and refuses a live socket, a file or link that is not a socket, and any probe that proves nothing, the tunnel's rule, in one shared decision. Its socket's directory is made 0700 whatever the umask, and an existing one that group or others can enter is refused, naming it: the directory is what keeps another account out, since BSD-derived systems may not enforce a socket's mode on connect.
