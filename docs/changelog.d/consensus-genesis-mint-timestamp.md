- **Consensus: the genesis block carries its mint time** (`NETWORK_IDENTITY.md` NI-R18; Rick, 2026-11-15). Every network's genesis header used to carry timestamp 0, so the timestamp rule, whose median looks back past genesis, let block 1 claim a time of 1. Genesis now carries the second its network was minted, taken from the clock by the genesis tool's new `geblock mint --network <name>` and recorded beside the network's other pins (`rust/shekyl-network/genesis/<name>.timestamp`). Every rebuild, the node's included, reads it back, and blocks 1 to 6 must be later than it. A genesis timestamp can't be zero: the type is non-zero, and a pin file holding zero fails the build. `geblock pin` never reads the clock and refuses a network with no recorded mint time; `geblock verify` checks the recorded time against the compiled table; `geblock mint` refuses a clock before 2026-08-04. All four networks were minted at 2026-11-15 16:40:28 UTC, so every genesis hash and network id has moved once more: a node's existing data directory is refused at open, and it starts fresh. Mainnet's genesis is still provisional and is minted again at its ceremony.
