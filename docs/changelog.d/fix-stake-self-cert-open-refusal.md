- **A wallet open refused by the random-number check has its own code, and the wallet contract compiles with the engine's `conformance` feature on.** With `conformance`, `shekyl-engine-core` checks this computer's random-number source before the wallet stakes, and refuses the open when the source fails (S6). The refusal's `OpenError::StakeRngSelfCertFailed` existed only in that build, so turning the feature on changed the error's shape, and `shekyl-wallet-contract`'s mapping, which names every arm, stopped compiling (`cargo check --workspace --all-features`). The variant is now in every build. Its payload `StakeSelfCertFailure` has no values without the feature, so the default build still cannot construct it and carries no float grader. The contract maps it to the new `-29017 RANDOM_SOURCE_CHECK_FAILED`: try once more (the check's false alarms are about one in a million), and on a second failure open the wallet on another computer. The grade goes to the server log. Wallet RPC contract 0.20.0; api_version stays 1. CI's x86_64 conformance lane now lints the contract with the feature on.
