- **CI: a red run on `dev` opens an issue, and flaky and slow tests are named on every Rust run** (`.github/workflows/report-dev-red.yml`, `scripts/ci/nextest_report.py`, `50-testing.mdc` "A flaky test is a finding, not a pass"). A failed push run of the build or Rust workflow on `dev` opens, or comments on, one `dev RED: <workflow>` issue naming the failed jobs and every pull request merged since that workflow last passed there; `scripts/ci/check_dev_red_reporter.py` keeps each reporter needing every job of its workflow. The Rust job retries a failing test once and lists a test that passed only on the retry under "Flaky" in its summary and as a warning on the pull request; two flakes of one test in seven days quarantine it with a date and an owner. A test still running at 30 minutes is killed by name, and fails when its retry is killed too. The summary also lists the twenty slowest tests and the five binaries with the most test time, and the test phase is three steps (build, run, doctests) so the job's step times separate compiling from running. Two runs that repeated work are cut: the separate release run of the 10,000-case `prop_round_trip` property (the workspace run checks the same cases in debug, which also catches overflow, and the nightly runs 200,000 in release), and the doctests in `shekyl-engine-core`'s `conformance` rerun, which the feature does not change.
