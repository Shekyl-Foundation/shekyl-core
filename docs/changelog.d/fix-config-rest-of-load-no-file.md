- **A test that is not about the configuration file no longer reads the host's** (`shekyl-daemon-config` `load`).
  - **What was wrong.** Six `shekyl-daemon` tests (one in `run_tests.rs`, five in `verify.rs`) called `load` with no `--config-file`, so `load` read the network's default file, `/etc/shekyl/shekyld-<network>.toml`. On a host that runs a daemon they took that daemon's settings. Three other test helpers avoided the file by copying `load`'s later steps, and a copy skips any step `load` gains afterwards.
  - **Now.** `load` is its file step and `after_file`, which takes the opened file as an `Option` and does everything else. `load` composes the two. The six tests and the three helpers call `after_file` with `None`, which is production's own value where the default file is absent. `choosers`, `resolve` and `sections::build` are `pub(crate)`, so a new copy of the composition outside the crate does not compile.
  - The named-file path keeps its end-to-end test, `shekyl-daemon/tests/config_file.rs`.
  - **The entry point's tests.** Seventeen more tests start the daemon through `run::main` with no `--config-file`: six in `shekyl-daemon`'s `run` and `verify` test modules and eleven in four of its integration tests (`interrupt_inherited_ignore`, `owner_socket`, `owning_connection`, `service_rendezvous`). `main` calls `load`, so they read the default file too. `main` is now `main_loading` with `load` as its load step, and those tests pass `load_default_file_unread`, which is `load` with one difference: when the command line names no file, none is opened. A named file is still read and checked. There is one body of `main` and one of `load`.
  - **How the seventeen were found.** With the default-file arm of the loader made to panic, they are the tests that fail in the six crates that depend on `shekyl-daemon-config`; after the change none does.
