- **One string per address (R-23).** The single-signer address decoder used `bech32::decode`, which accepts an all-uppercase string and the older Bech32 checksum as well as Bech32m, so one address had several strings that all decoded. Every Shekyl Bech32m string (address segments, multisig fingerprints, wallet proofs, message signatures) is now read by `shekyl-encoding::decode_blob`, the one codec. It refuses any checksum but Bech32m's (`EncodingError::Checksum`) and anything that is not Bech32 at all (`EncodingError::Malformed`), any string that decodes to bytes re-encoding to a different string (`EncodingError::NotCanonical`: non-zero padding bits, or one more zero character where the padding stays under a byte), and the canonical string written with an uppercase letter (`EncodingError::NotLowercase`; a string that is no Bech32m in any case is named for that, not for its capitals). `shekyl-address` writes and reads its segments and fingerprints through it rather than open-coding Bech32m, `AddressError::Encoding(String)` and `MultisigAddressError::Encoding(String)` become typed `Bech32m(EncodingError)` variants (with `MultisigAddressError::FingerprintLength` for a wrong-sized fingerprint), and HRP lookups compare exactly. The wallet names the case refusal: "recipient address must be written in lowercase". An upper-cased fingerprint and an upper-cased wallet proof, each of which a test previously pinned as accepted, are refused, and proof decoding compares its HRP exactly. Rule 65 gains the rule; the address spec (`FCMP_PLUS_PLUS.md` §11) states it; the FOLLOWUPS row on Bech32m variant enforcement is closed.
