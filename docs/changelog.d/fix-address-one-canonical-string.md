- **One string per address (R-23).** The single-signer address decoder used `bech32::decode`, which accepts an all-uppercase string and the older Bech32 checksum as well as Bech32m, so one address had several strings that all decoded. Every Shekyl Bech32m string (address segments, multisig fingerprints, wallet proofs, message signatures) is now read by `shekyl-encoding::decode_blob`, the one codec. It refuses any uppercase letter (`EncodingError::NotLowercase`), any checksum but Bech32m's, and any string that decodes to bytes re-encoding to a different string (`EncodingError::NotCanonical`, non-zero padding for one). `shekyl-address` writes and reads its segments and fingerprints through it rather than open-coding Bech32m, `AddressError::Encoding(String)` and `MultisigAddressError::Encoding(String)` become typed `Bech32m(EncodingError)` variants (with `MultisigAddressError::FingerprintLength` for a wrong-sized fingerprint), and HRP lookups compare exactly. The wallet names the case refusal: "recipient address must be written in lowercase". An upper-cased fingerprint, which a test previously pinned as accepted, is refused. Rule 65 gains the rule; the address spec (`FCMP_PLUS_PLUS.md` §11) states it; the FOLLOWUPS row on Bech32m variant enforcement is closed.
