- **The wallet verifies its own membership proof before a spend leaves it.** In a release build the FCMP++ prover checks almost none of its own work, and it does not read the tree root it is given, so a prover fault or a tree path that does not reach the wallet's root used to surface only as the daemon's refusal after the transaction was on the wire. `sign_transaction` now verifies the proof it has just made with the consensus verifier (`shekyl_fcmp::proof::verify`), over the key images, spend-slot PQC keys, root, layer count and signed message the daemon will use, and refuses with the signer fault `membership-self-check` (wallet RPC `-29119`) when it does not verify. Every assembly path, ordinary transfers and drains as well as bonds and claims, then holds the transaction's key images and spend-slot keys to the ones the proof was verified against, and refuses with the same fault when they differ. The cost is one proof verification per transfer, far below the proving it follows.
- **Secret scalars decode without an unwiped copy.** Every decode of secret bytes in `shekyl-crypto-pq` now goes through one helper that reads them from zeroizing scratch, where the library's by-value decode left a copy of each secret on the stack. Which encodings are accepted does not change.
