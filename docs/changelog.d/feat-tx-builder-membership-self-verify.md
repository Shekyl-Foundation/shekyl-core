- **The wallet verifies its own membership proof before a spend leaves it.** In a release build the FCMP++ prover checks almost none of its own work, and it does not read the tree root it is given, so a prover fault or a tree path that does not reach the wallet's root used to surface only as the daemon's refusal after the transaction was on the wire. `sign_transaction` now verifies the proof it has just made with the consensus verifier (`shekyl_fcmp::proof::verify`), over the key images, spend-slot PQC keys, root, layer count and signed message the daemon will use, and refuses with the signer fault `membership-self-check` (wallet RPC `-29119`) when it does not verify. `open_spend` holds the transaction's key images to the ones the proof was verified against. The cost is one proof verification per transfer, far below the proving it follows.
