- **Daemon: the configuration file's group check no longer fails on a host whose directory service is stopped.** The check that a secret-holding configuration file's group has no member besides the daemon's account walks the system's accounts. On glibc with `sss` in `nsswitch.conf` and `sssd` stopped, a complete walk ends with `errno` set to `ENOENT`, which the walk read as an unfinished read, so the daemon refused its own configuration file. The walk now uses `getpwent_r` where the C library has it, and reads the end of the list from its return code: `ENOENT` on glibc (where a too-small buffer is retried with a larger one, because glibc returns the same entry again), `0` with no entry on FreeBSD and DragonFly (where a too-small buffer refuses, because those libraries move past the entry). musl, macOS, OpenBSD, illumos and Solaris have no `getpwent_r` the build can call and keep the `errno` walk. Every other outcome still refuses, and a target the code does not name does not build. A directory service that is stopped, or that does not list its accounts, is treated as listing none of them; the operator docs already say to keep the daemon's group a local group.
