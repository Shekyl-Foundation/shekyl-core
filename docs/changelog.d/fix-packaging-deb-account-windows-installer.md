- **Packages: one daemon per network, an account that is never someone's login, and a Windows installer that carries Tor** (`INPUT_GRAMMAR.md` IG-Q64, all of it but the Windows machine root; IG-F12 and IG-F16 closed, IG-F13's Linux half; found preparing alpha.12's fleet install). The packaged unit ran mainnet only, as an account no package created, and the `.rpm` shipped no unit at all. Both packages now carry the template `shekyld@.service`: `systemctl enable --now shekyld@testnet` runs that network, as `--service --network %i` with its own data (`/var/lib/shekyl/<network>`) and log (`/var/log/shekyl/<network>/shekyld.log`), and checks its settings with `--config-verify` as the daemon's account before every start, so a bad file is refused with its typed reason before anything is created. Networks run side by side and share `/run/shekyl`, which survives one instance stopping. The account and `/etc/shekyl` are declared (`sysusers.d`: system account `shekyl`, no home, no login shell; `tmpfiles.d`: `/etc/shekyl` `root:shekyl` `0750`), and each public network's settings file, every option commented out under a header that says how the unit uses it, is placed `root:shekyl` `0640` when none is there and never overwritten. Before any file is unpacked the packages refuse an existing `shekyl` that is a login (a shell, an administrators' group, a sudo rule) or a `shekyl` group another account uses, because the daemon would run with that login's rights (Rick, 2026-11-18); the refusal names the rename. Neither package enables, starts or restarts the daemon. Removal stops and disables every instance and keeps the account, `/etc/shekyl` and the data; purging the `.deb` removes the per-network files and then `/etc/shekyl` if nothing else is in it. The `.deb` is built with `dpkg-deb` and its own maintainer scripts, because fpm runs no purge script. The recipe gate holds the template: one start, and one check that is the start plus `--config-verify`. Tested on Debian 12 and 13, Ubuntu 22.04 and 24.04 and Rocky 9, and on a Rocky Linux 9 host under systemd with SELinux enforcing (two networks, a refused file, erase; no SELinux denial). The Windows installer copied only the executables, so an installed daemon had no Tor where it looks on Windows (`tor\` beside `shekyld.exe`) and, under the default `tor = managed`, none to run; it now installs the pinned `tor.exe` and its licences (clearing an earlier release's first), `shekyl-rpc-tunnel.exe` and the settings example, drops the `shekyl-cli` entries and shortcut Windows never shipped, and the package job checks the installer's Tor against its pin. The package job runs on ubuntu-24.04: 22.04's p7zip 16.02 cannot read the installer and, asked for `tor\` alone, returns wrong bytes.
