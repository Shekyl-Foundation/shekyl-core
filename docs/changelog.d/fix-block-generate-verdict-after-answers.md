- **`dev_block_generate` reads the chain after the door has answered every block the miner delivered.** A block already handed to the door could still be connecting when a withdrawal won the race, and the call reported `mine.syncing` for a block that joined a moment later. A caller that retried then mined one block more (the dialing regtest gate stood at 22 blocks for 21). The call stops the miner, waits until the door has replied to every block delivered before the wait, and only then reads the tip. The shutdown handle that closes the found-block inbox is not a receiver, so a sink that dies does not leave that wait parked for the life of the node.
