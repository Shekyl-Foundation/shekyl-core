- **`shekyl-cli` survives its output being closed.** When the program reading its output goes away (a closed terminal, a parent that crashed, `shekyl-cli … | head`), the CLI used to abort on its next write: the open wallet was not closed or saved, and the private directory of its built-in wallet server (`shekyl-rpc-<pid>-<n>` in `$XDG_RUNTIME_DIR` or the temp directory) was left behind. Now it ends the session the way the end of its input does, closing and saving the wallet and removing that directory, writes one line to standard error, and exits with status 1. Every output line goes through one writer that cannot abort the process.
- **Leftover wallet-server directories are cleaned up.** When `shekyl-cli` starts its built-in wallet server, it removes the `shekyl-rpc-<pid>-<n>` directories that an earlier run of this account left when it was killed, and only those: one whose process no longer runs, owned by this account. A running process's directory is never touched.
- **A cleanup that fails is said.** If the server cannot remove its socket or its directory at shutdown, `shekyl-cli` prints a warning naming the path, instead of leaving it silently.
