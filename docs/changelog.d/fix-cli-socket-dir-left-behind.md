- **`shekyl-cli` survives its output being closed.** When the program reading its output goes away (a closed terminal, a parent that crashed, `shekyl-cli … | head`), the CLI used to abort on its next write: the open wallet was not closed or saved, and the private directory of its built-in wallet server (`shekyl-rpc-<pid>-<n>` in `$XDG_RUNTIME_DIR` or the temp directory) was left behind. Now it ends the session the way the end of its input does and removes that directory, writes one line to standard error, and exits with status 1. The line says the wallet was closed and saved when that close succeeded, and says it could not be closed when it did not. A money command whose summary did not land is refused and nothing is sent. A seed that could not be shown is a failure: the wallet was created, so delete it and create it again where the output can be read. Every output line goes through one writer that cannot abort the process.
- **Leftover wallet-server directories are cleaned up.** When `shekyl-cli` starts its built-in wallet server, it removes the `shekyl-rpc-<pid>-<n>` directories that this account owns and that no running server still holds. A directory a server still holds is never touched.
- **A cleanup that fails is said.** If the server cannot remove its socket or its directory at shutdown, `shekyl-cli` prints a warning naming the path, including when the server's own task failed as well.
