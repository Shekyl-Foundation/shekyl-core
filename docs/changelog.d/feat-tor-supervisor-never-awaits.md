- **The managed Tor supervisor never waits on Tor** (`TOR_SUPERVISOR.md` §4.11; Rick, 2026-11-10). Each request to Tor is sent and the supervisor returns to its inbox: the stop and reap of a Tor that ended (up to 5 s for a frozen one, which ignores the close), the launch with its directory work, the event subscription, the sample, `SETCONF`, the republish's delete and add, the refetch, and the directory check and its fetches. The reply arrives later as one more message. The supervisor used to stop and wait up to 30 s for each reply, and a status question or a stop asked meanwhile waited with it. That is exactly when an operator asks what is wrong with Tor. A status question and the stop are now answered at once, from the one place that holds the state. The 30 s reply bound is the supervisor core's own deadline for the request in flight, in awake time. One request is in flight at a time, in the order the waits gave, so no decision changes.
