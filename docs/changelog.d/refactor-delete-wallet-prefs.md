- **A wallet keeps no preferences file** (Rick, 2026-11-21). The `<wallet>.prefs.toml` / `.prefs.toml.hmac` pair and the `shekyl-engine-prefs` crate are deleted, and with them the torn write that, when the process was killed between the two writes, set good settings aside as tampered and reset them. A pair an earlier build left beside a wallet is no longer read, moved or deleted; you may remove it. Only one of its settings was read anywhere; the others were Monero's carried over (`docs/WALLET_SETTINGS.md` §6).
- **The Tor binary a serving wallet runs is now an option: `--tor-file <path>`** on `shekyl-wallet-rpc`, and on `shekyl-cli` for its own server (refused with `--rpc-url`, which starts none). If you set `device.tor_binary_path` in a prefs file (on FreeBSD, say), pass that path as `--tor-file` instead. Unset, the bundled Tor is found as before. A relative path, or one naming no file on this machine, refuses the start and says how to fix it, as `shekyld`'s `tor-file` does; the binary must still match the pinned build.
- **`shekyl-cli` refuses the coin-selection settings by name** (`min-outputs-count`, `min-outputs-value`, `ignore-outputs-above`, `ignore-outputs-below`, `merge-destinations`) with the reason: a human choice on a visible transaction parameter becomes a pattern, while the wallet's deterministic selection gives every wallet the same shapes.
