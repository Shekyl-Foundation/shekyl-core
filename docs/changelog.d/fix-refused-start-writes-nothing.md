- **A daemon start that a store refuses no longer writes to its stores, its marker or its RPC files.** Opening a redb file writable rewrites its header even when nothing else changes, and the daemon judged each store only as it opened it, so a start refused by a later store (a foreign pool file, a chain file from another release) had already rewritten the earlier ones, and the RPC channel's files besides. Every store — the chain file, the pool file and the RPC enrollment store — is now checked read-only, by the same decision its open makes, right after the data directory's lock is taken and before anything is written. A file the engine must repair first, an unfinished initialization and the older chain layout the pre-genesis wipe replaces are still acted on by the open that follows. The check also refuses a store file the daemon could not write, a dangling link at a store's path, and an RPC enrollment store whose table has another type. A refused start still takes the data directory's lock and appends its refusal to the configured log file.
