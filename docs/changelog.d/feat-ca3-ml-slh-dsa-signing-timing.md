- **A timing harness for ML-DSA-65 transaction authorisation and SLH-DSA-192s message signing (`CA-3`).** `shekyl-crypto-pq`'s example `ca3_pq_sign_timing` times the two shipped entries, key derivation included: `sign_pqc_auth_for_output` through its seeded twin, and `sign_message_pq_half` hedged with the OS's randomness. Each mode compares a fixed secret against fresh ones and two fixed secrets against each other, with nulls, a planted control, and a check that every signature returned and every kept one verifies. `CRYPTO_AUDIT.md` §3.2 and §3.3 record each signer's threat model and source read. Both find very low exposure: an ML-DSA output key signs about once, and the SLH-DSA key's timing work depends only on values the signature reveals, since fips205 0.5.0 made the hash count constant. ML-DSA's rejection samplers vary in time by design, and the crate's own constant-time harness bypasses them. The development run shows the familiarity pattern on a repeated key.
