- **A test can reproduce a spend byte for byte, and no shipped binary can** (`CHAIN_FORGE.md` `CF-1b`). The FCMP++ prover, the transaction builder, the hybrid signers and the harness spender each gain a seeded entry point behind a test-only `seeded-rng` feature: a fixed seed gives the same proof and the same signatures every run. The production entry points still draw from the operating system and take no randomness from their caller. `prove_with_rng`, which any crate could call before, now exists only under that feature. The harness draws each spend's seeds on the planning thread, one fresh pair per spend, and hands that pair to the spend. The spender holds no generator, so two threads that share it cannot draw in scheduler order. A Schnorr-style proof must not reuse its nonces across two statements.
- **The per-input shared secret is wiped when the builder drops it** (rule 35). `shekyl-tx-builder`'s `sign_pqc_auths` copied each input's combined KEM shared secret into a plain stack array to sign that input's post-quantum authorization, and nothing wiped the copy. The copy is now `Zeroizing`, so the bytes are wiped on drop.
- **Two gates prove the seams stay out of every release.** The production graph check resolves this repository's release as cargo builds it, every platform included, and the GUI wallet's release, from a pinned list of its shekyl-core dependencies that CI and a nightly hold to the wallet's manifest. It fails if a harness crate or any test-only feature is on. The seedable-RNG gate fails on any seeded generator in that shipped code, or in a crate headed for production, unless its site is listed with where its seed comes from. A listing that waits on a named increment expires when that increment lands.
- **The harness network id is test-only.** `HARNESS_NETWORK_ID` sits behind `shekyl-network`'s test-only `harness` feature, and `Spender::over`, which signed under it without saying so, is gone: every harness spender names the chain it spends on.
