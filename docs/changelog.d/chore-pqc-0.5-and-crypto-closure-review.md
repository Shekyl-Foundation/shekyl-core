- **ML-KEM, ML-DSA and SLH-DSA run on fips203, fips204 and fips205 0.5.0.** Each is declared once, exactly pinned, and every consumer inherits it. Keys, ciphertexts, shared secrets and signatures are byte-identical to 0.4 on Shekyl's own entry points (60,000 ML-KEM, 3,000 ML-DSA-65 and 40 SLH-DSA-192s seeds compared), and every KAT and ACVP vector passes unchanged. Decapsulation now rounds Decompress to nearest, as FIPS 203 requires, held by upstream's regression vector. A stored decapsulation key with a coefficient of q or more is refused as a malformed decapsulation key, and a signing key with a secret coefficient out of range as a malformed signing key; each refusal has its own error.
- **The held crypto crates are reviewed.** Every package the crypto-closure record held behind its newest compatible release was read at source and admitted with the reason in `rust/.cargo/crypto-closure.toml`: zeroize 1.9.2 (a wipe is a fill plus an opaque barrier on asm targets, and `Zeroizing`'s `Debug` prints nothing), aes 0.9.4 (RandomX's rounds, tested on the CPU and software paths of x86_64 and aarch64), the RustCrypto core types, rand 0.8.8, zerocopy 0.8.64, bitvec 1.1.1, the mnemonic's NFKD tables (Unicode 18), FROST on modular-frost 0.11.1 with multiexp 0.5's constant-time table selection, and the closure's serialization and platform crates. The FCMP++ prover stays on multiexp 0.4, whose constant-time multiexp indexes its tables by secret bits; moving it belongs to the DRS lane, with a Pi 4 prover timing. The fuzz locks and the GUI wallet's lock move with the workspace lock.
- **The redb crates' tests run on Windows in CI.** The MSVC job runs the chain store's tests and those of every redb crate the daemon links there, each test binary held to a floor. `scripts/ci/fetch_test_chain.py` fetches the hosted test chains on Windows and FreeBSD (oras pinned for both from its release's checksums), and refuses a Python older than 3.11 by name.
